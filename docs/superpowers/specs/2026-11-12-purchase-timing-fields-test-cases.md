# 購入タイミング計算用の登録項目 論理テストケース（PTF）

## メタデータ

| 項目 | 値 |
|---|---|
| 対応仕様 | `docs/superpowers/specs/2026-11-12-purchase-timing-fields-design.md`（PTF、2026-11-22承認） |

| 状態 | Draft |
| 作成日 | 2026-11-22 |

## 1. 目的

購入物の登録に購入単位・1単位あたりの日数・余裕日数・在庫を数えた日時を加え、消費スピードを改名する変更について、承認済み仕様から導出した実装非依存のテストケースを定義する。

この文書ではテストレベルや実装方法を決定しない。実装前の最小TDDセットは、人間による承認後に別途選定する。

## 2. 基準となる有効入力

特に入力値を指定しないテストでは、以下を基準とする。

| 項目 | 値 |
|---|---|
| 名前 | 牛乳 |
| カテゴリ | 食品 |
| 購入単位 | パック |
| 1単位あたりの日数 | 3 |
| 余裕日数 | 0 |
| 在庫（購入単位） | 2 |
| 一時的な購入 | false |

## 3. PURC第2版の論理テストケースとの関係

PURC第3版では、次の第2版テストケースをPTFのテストケースで置き換える。その他のPURCテストケースは、基準入力をこの文書の2章に読み替えてそのまま有効とする。

| 第2版のTest Case ID | 置き換え先 | 理由 |
|---|---|---|
| PURC-002-TC1 | PTF-001-TC1、PTF-014-TC1 | 入力項目が5項目から7項目になる |
| PURC-002-TC2 | PTF-003-TC1 | 初期値の対象項目が増える |
| PURC-004-TC7 | PTF-002-TC1 | 上限が100,000から365になる |
| PURC-004-TC8 | PTF-002-TC2、PTF-005-TC1 | 上限超過の値が変わる |
| PURC-004-TC11、TC12 | PTF-002-TC3 | 0の意味を1単位あたりの日数で確認する |
| PURC-012-TC1 | PTF-009-TC1、PTF-015-TC2 | 表示項目が変わる |

## 4. 項目と改名

| Test Case ID | 対応仕様ID | 前提 | 操作 | 期待結果 |
|---|---|---|---|---|

| PTF-001-TC2 | PTF-001 | 1単位あたりの日数を含む有効な入力である | APIへ登録要求を送信する | 登録され、レスポンスと再取得した購入物の1単位あたりの日数が入力値と一致し、旧名の消費スピード（`speed`）はレスポンスに含まれない |

## 6. 在庫を数えた日時

| Test Case ID | 対応仕様ID | 前提 | 操作 | 期待結果 |
|---|---|---|---|---|
| PTF-006-TC1 | PTF-006 | 有効な入力である | 登録する | レスポンスと再取得した購入物に在庫を数えた日時があり、作成日時と同じ時刻である |
| PTF-006-TC2 | PTF-006 | リクエストに在庫を数えた日時（過去の任意の時刻）を含めている | APIへ登録要求を送信する | 登録され、在庫を数えた日時はリクエストの値ではなく作成日時と同じ時刻になる |
| PTF-007-TC1 | PTF-007 | 購入物が登録済みである | 編集で名前とカテゴリだけを変更する | 更新日時は変わり、在庫を数えた日時は登録時の値のままである |

| PTF-013-TC2 | PTF-013 | 購入物が在庫2で登録済みである | 編集で在庫を2のまま、名前を変更する | 在庫を数えた日時は登録時の値のままである |
