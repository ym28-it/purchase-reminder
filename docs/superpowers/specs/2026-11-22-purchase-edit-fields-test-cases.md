## 1. 目的

購入物の編集で、登録と同じ全項目を変更でき、同じ入力が登録と編集で同じ判定になる変更について、承認済み仕様から導出した実装非依存のテストケースを定義する。

この文書ではテストレベルや実装方法を決定しない。実装前の最小TDDセットは、人間による承認後に別途選定する。

## 2. 基準となる入力

特に指定しないテストでは、次の購入物が登録済みで、編集の入力も次の値を基準とする。

| 項目 | 値 |
|---|---|
| 名前 | 牛乳 |
| カテゴリ | 食品 |
| 購入単位 | パック |
| 1単位あたりの日数 | 3 |
| 余裕日数 | 0 |
| 在庫（購入単位） | 2 |
| 一時的な購入 | false |

「編集の入力」は、編集で送る全7項目を指す。「保存済みの購入物が変わらない」は、再取得した購入物の全項目と更新日時が編集前と同じであることを指す。

## 3. 既存のテストケースとの関係

PEDTは、次の既存テストケースの期待を置き換える。その他のPURC・PTFのテストケースは、編集に関するものを含めてそのまま有効とする。

| 既存のTest Case ID | 置き換え先 | 理由 |
|---|---|---|
| PTF-012-TC1 | PEDT-005-TC1、PEDT-010-TC1 | 編集で`unit`・`buffer_days`を変更できるようになる（引き継ぎではなくなる） |
| PURC-004-TC10、PTF-004-TC2のうち、編集に小数の在庫を許す前提 | PEDT-002-TC2 | 編集でも在庫は整数だけを受け付ける |

PTF-012-TC2（編集画面に保存済みの1単位あたりの日数が表示される）、PTF-012-TC3（削除）、PTF-007-TC1、PTF-013-TC1、PTF-013-TC2、PTF-016-TC1、PURC-022〜024のテストケースは期待が変わらない。ただし、編集の入力に`unit`と`buffer_days`を含める必要が生じる。

## 4. 編集で受け付ける項目（PEDT-001、PEDT-003、PEDT-004）

| Test Case ID | 対応仕様ID | 前提 | 操作 | 期待結果 |
|---|---|---|---|---|
| PEDT-001-TC1 | PEDT-001 | 購入物が登録済みである | 全7項目に別の有効な値（名前「豆乳」、カテゴリ「飲料」、購入単位「本」、1単位あたりの日数5、余裕日数2、在庫7、一時的な購入true）を指定してAPIへ編集要求を送信する | HTTP 200が返り、再取得した購入物の全7項目が送った値と一致する |
| PEDT-001-TC2 | PEDT-001 | 購入物が登録済みである | 名前、カテゴリ、購入単位、1単位あたりの日数、余裕日数、在庫、一時的な購入のうち1項目だけを欠いて、項目ごとにAPIへ編集要求を送信する | いずれもHTTP 422が返り、欠けた項目を識別できる。一時的な購入が欠けた場合もfalseとして保存されない。保存済みの購入物は変わらない |
| PEDT-001-TC3 | PEDT-001 | 購入物が登録済みで、作成日時と在庫を数えた日時を控えている | 有効な編集の入力に、在庫を数えた日時、作成日時、更新日時、ID（別の値）、旧名の消費スピード（`speed`）を加えてAPIへ編集要求を送信する | HTTP 200が返り、加えた値は保存されない。作成日時とIDは変わらず、在庫を数えた日時は在庫の変更有無だけで決まる（PEDT-006）。レスポンスに`speed`は含まれない |
| PEDT-003-TC1 | PEDT-003 | 1単位あたりの日数が3で登録済みである | 一時的な購入がtrueとfalseの場合に、それぞれ1単位あたりの日数を0にして編集する | どちらも範囲を理由に拒否されず、1単位あたりの日数0で保存される |
| PEDT-004-TC1 | PEDT-004 | 購入物が登録済みである | 1単位あたりの日数366と余裕日数31の2項目が同時に範囲外の編集の入力を、APIへ送信する | HTTP 422が返り、1単位あたりの日数と余裕日数の両方を項目ごとに識別できる。保存済みの購入物は変わらない |

## 9. 確認事項（Logical Test Case Gateで決める事項）

- **LTC-1（PEDT-001-TC3）**: 決定済み（2026-11-22 ym28-it、案a）。編集の入力に、クライアントから受け取らない項目（在庫を数えた日時、作成日時、更新日時、ID）や旧名`speed`が含まれていても、未知または受け取らない項目として無視し、編集は通常どおり成功する（登録のPTF-006-TC2、PTF-001-TC4と同じ扱い）
- 編集ダイアログの失敗表示（サーバーが422・409を返したときの表示、保存中のボタン無効化など）は、PEDTが仕様化していない。現状の挙動を変えない範囲として、この文書ではテストケース化しない。
